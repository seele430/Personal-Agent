# Personal Agent

> 一个跑在本地的个人 AI 工作台。核心特色是**多 Bot 正式辩论**：多个 AI 按真实赛制分阶段交锋，最后投票分出胜负。

---

## 这是什么

不是"多个 Bot 各自回答一遍"，而是**有赛制、有约束、有裁判**的辩论：

```
主持人开场 → 双方立论 → 双方驳论 → 轮流质询 → 交锋（限时）→ 双方结辩 → 评委投票 → 复盘
```

每个阶段有**不同的发言约束**（引用对方原话、指明打哪一层、不许引入新论点……），
这些约束才是"让 AI 真的辩论"而不是"轮流表白立场"的关键。

除聊天室外，还有提醒、任务、额度、Bot 管理等个人助手功能。

## 核心设计：为什么是这四件事

### ① 用「阶段状态机」而不是让 AI 自由对话

自由对话的 AI 会迅速滑向**互相附和**（"你说得对，我也这么认为"）——
这是对齐训练的副作用，不是模型不够聪明。

所以把辩论切成 8 个阶段，**每个阶段给不同的硬约束**：

| 阶段 | 约束 |
|---|---|
| **立论** | 必须给出：立场 / 判断标准 / 核心论证 / 局限 / 结语 |
| **驳论** | 必须**引用对方原话**（「」标出），并指明打的是哪一层：事实 / 推理 / 前提 / 反例 |
| **质询** | 只问**一个**可回答的问题，直指对方的前提或标准 |
| **交锋** | 回合制：回应 → 反击（引用原话）→ 影响 → 推进，**沿用当前争点** |
| **结辩** | **不许引入新论点**，只能总结已说过的 + 承认本方最薄弱处 |

### ② 主持人必须是独立角色

裁判不能有立场。主持人（host）：
- **不参与辩论**，只串场、汇总、主持投票
- 在 `room_bots` 里**没有 stance**
- 汇总输出结构化 JSON（共识 / 分歧 / 决策选项），前端渲染成可读段落

### ③ 交锋必须回合制，而且要「接得上」

第一版是"一次性生成 N 轮"——结果 6 条发言同时怼出来，读起来是**轮流独白**，不是交锋。

改成**一次一位**：

```
点「进入交锋」→ 只出第一位一条
点「下一位发言」→ 轮到下一位（按 joined_at 顺序，即拉进房间的顺序）
3 分钟倒计时结束 → 自动进结辩
```

而且每次生成都**把对方最近一句喂进去**，否则两边只会复读立场。

### ④ `stage` 存在「消息」上，不是房间上

房间有 `stage`（当前阶段），**每条消息也有 `stage`**（它属于哪个阶段）。

这样：
- 聊天气泡之间的**阶段分割线**可以精确画出来
- 用户中途发的消息**继承当前阶段**，不会插出莫名其妙的分割线
- 回看历史时，能知道这句话是立论还是结辩

## 快速开始

```powershell
# 1. 依赖
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt

cd frontend
npm install
cd ..

# 2. 配置（需要 DeepSeek API Key）
#    在 .env 里写：DEEPSEEK_API_KEY=sk-xxxx

# 3. 一键启动（api:8000 / scheduler / outbox / frontend:5173）
.\scripts\run-dev.ps1

# 停止
.\scripts\run-dev.ps1 -Stop
```

打开 <http://127.0.0.1:5173>。

## 设计取舍记录

- **不做流式输出**：辩论发言需要完整结构（立场/论证/局限），流式反而割裂阅读体验。
- **不做自动推进**：阶段由用户点按钮推进，因为"看 AI 吵架"的乐趣在于掌控节奏。
- **语音用 Edge TTS 而非云端付费 TTS**：神经网络音质已够用，且完全免费。
