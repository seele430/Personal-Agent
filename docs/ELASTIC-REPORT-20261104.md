## 2.1 摘要

平台已具备弹性计算岗位关心的**控制面骨架**：统一契约、生命周期、租约与最小负载调度、有界队列与背压、全链路取消、轨迹与审计。
但**可量化的运营数据仍不完整**：缺调度均衡度、缺长压测与资源采样、缺冷启动/回收时延分布。
本报告给出要展现的五类数据、口径、目标值，以及 4 周补齐计划。

## 2.3 要展现的五类数据

### ① 规模与容量

| 指标 | 口径 | 目标 |
|---|---|---|
| 并发沙箱数 | 非 reclaimed 的 sandbox 数 | 单机 ≥ 8（当前配额），可调到 16 |
| 创建速率 | 成功 create / 秒（开环） | 待测，目标给出实测值 |
| exec 吞吐 | 成功 exec / 秒 | 以 8 RPS 为稳定点 |
| 调度域 | 节点数 × 核数 | 1 节点 × 12 核（多节点为模拟） |

### ② 调度质量（弹性计算岗最关注）

| 指标 | 算法 | 目标 |
|---|---|---|
| 均衡度 | `1 - stdev(节点活跃数) / mean` | ≥ 0.90 |
| 最大最小比 | `max / min`（min=0 单列） | 尽量 ≤ 2 |
| 调度时延 | create→选节点 | p99 < 10 ms |
| 失败分类 | `NO_READY_NODE` vs `CAPACITY_EXCEEDED` | 两类都要有测试 |

### ③ 弹性与冷启动

| 指标 | 定义 | 目标 |
|---|---|---|
| 冷启动 p50/p99 | create→ready | 待测，给真实分布 |
| 回收时延 | destroy/TTL→资源释放 | p99 < 1 s |
| 回收残留 | 进程 / 目录 / 非回收行 | **必须为 0** |
| 租约过期检测 | 停心跳→not_ready | ≈ 30 s（3 个周期） |

### ④ 资源效率

| 指标 | 口径 | 诚实边界 |
|---|---|---|
| 密度 | 并发沙箱 / 逻辑核 | 单机可测，不与 DSec 比绝对值 |
| 每沙箱内存 | RSS / 沙箱数 | 需 psutil 采样 |
| 超卖比 | 分配 / 物理 | 不做内存共享，恒为 1:1 |
| CPU 利用率 | 压测期间均值/峰值 | 配合饱和曲线说明瓶颈 |

## 2.5 测量方法学（会被追问的四点）

1. **开环固定 RPS**：不用闭环，避免服务端拖慢导致测不出拐点。
2. **预热**：每档丢弃前 30 s，避免冷启动污染 p99。
3. **重复**：关键档 ≥ 3 次，报中位数与区间，不挑最好的一次。
4. **判据预定义**：拐点定义（如 p99 > 1 s 或错误率 > 1%）写在跑之前，跑完不改。

## 2.6 风险与边界

| 风险 | 影响 | 应对 |
|---|---|---|
| 单机资源有限（16 GB） | 并发与密度上不去 | 明确写“单机教学版”，不比绝对值 |
| 无 Docker / C++ 工具链 | 无法做多后端 | 只讲 tier1 + Job Object，撤回隔离承诺 |
| 长压测占机 | 跑机期间不能做别的 | 放后台任务，单档 10 min 串行 |
| 内存饥饿（本机常态） | 压测数据抖动 | 跑前关游戏/浏览器，记录环境 |
| 调度为单进程 SQLite | 不能宣称分布式 | 讲“机制复现”，不讲“集群” |

## 2.7 结论

- **能讲的**：控制面机制完整度、取消语义、队列背压、调度策略、可观测性。
- **还缺的**：三张图（均衡度、饱和曲线、时延分布）和一份可追溯的结果表。
- **建议顺序**：先补调度数据（最能体现弹性计算思维），再长压测，最后时延与回收。
