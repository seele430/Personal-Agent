# 远程访问威胁模型（v1.2 手机只读预览）

> 日期：2026-11-07 / 范围：同一局域网内，手机通过 HTTPS 只读访问产物预览与下载
> 状态：**代码与单测完成；真机 HTTPS 未验证**（需要用户的手机 + 手动信任自签名证书）

---

## 1. 资产

| 资产 | 敏感度 | 说明 |
|---|---|---|
| 产物内容（预览/下载） | 高 | 可能含个人笔记、代码、报告 |
| owner 令牌 | 高 | 一旦泄露 = 完整只读权限 |
| 访问日志 | 中 | 含访问时间、路径、客户端地址 |
| 服务器私钥 | 高 | 泄露可被中间人利用 |

## 2. 威胁与缓解

| 威胁 | 缓解 | 残余风险 |
|---|---|---|
| 同网段其他人扫到端口 | 默认**关闭**；开启需 `PERSONAL_AGENT_REMOTE=1` + 令牌 ≥32 字符 | 端口被扫到会得到 401，但仍暴露服务存在 |
| 无令牌访问 | 401，且**不触达下游应用** | — |
| 令牌爆破 | 要求 ≥32 字符；未做限速 | **无限速**，弱令牌仍可能被离线猜 |
| 用写请求改数据 | 非 GET/HEAD 一律 403（在应用之前拦截） | — |
| 越权访问非白名单路径 | 前缀白名单（`/api/artifacts`、`/api/activity`、`/health`） | 白名单内若有写接口会漏；当前这些前缀下只有只读路由 |
| 令牌进日志 | 日志只记方法/路径（已剥离 query）/状态/耗时/UA，header 不整条落盘 | 若未来加 body 日志需重新评估 |
| 中间人窃听 | HTTPS + 自签名证书（SAN 含 LAN IP 与 localhost） | 自签名需手机手动信任；**未验证** |
| 私钥被同机其它用户读取 | 生成后 `icacls /inheritance:r` 收紧到当前用户 | 同账户下的恶意进程仍可读 |

## 3. 明确不做（本轮）

- 不做 QQ 入站控制（v1.2 边界）；
- 不做多用户 / 角色权限，只认一个 owner 令牌；
- 不做 reveal（敏感内容不进远程响应）；
- 不做公网暴露、端口转发、DDNS。

## 4. 验证状态

| 项 | 状态 | 证据 |
|---|---|---|
| 鉴权 401 / 放行 | ✅ 单测 | `tests/unit/test_remote_guard.py` |
| 写方法 403 且不触达应用 | ✅ 单测 | 同上（`app.calls == 0`） |
| 白名单边界 | ✅ 单测 | `/api/artifactsx` 被拒 |
| 日志脱敏 | ✅ 单测 | 日志里不含令牌 |
| 证书 SAN / 私钥权限 | ✅ 实测 | `pa-v12-evidence-20261107/tls/`（SAN: 10.224.76.60 + localhost） |
| **手机真机 HTTPS 访问** | ❌ **未验证** | 需要用户的手机在同一 WLAN 并手动信任证书 |

## 5. 上线前必须补的

1. **令牌限速**（当前无速率限制，32+ 字符只是提高爆破成本）；
2. 手机真机跑一次（证书信任 → 打开 `/api/artifacts` → 能看到列表）；
3. 若未来把远程白名单扩到含写接口，必须重新审这个模型。
