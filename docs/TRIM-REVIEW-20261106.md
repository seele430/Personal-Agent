# 个人版精简清单 · 复核意见

> 日期：2026-11-06
> 复核对象：`docs/PERSONAL-EDITION-TRIM-20261106.md`（Kimi 评审意见的整理版）
> 结论：**方向同意，但不能原样执行**——三处要改，两处漏项。

---

## 1. 总评

这份清单的骨架是对的：**删功能、不删防线**；把展示型材料降级为手动；测试分三层。
但有两类问题：

1. **有两项建议会削弱实际可用性/回归能力**（CLI 全删、压测全手动）；
2. **漏掉了个人版最要命的两件事**（数据备份恢复、本地暴露面）。

另外，“删邀请码”必须限定范围，否则会误伤登录本身。

---

## 2. 我同意的部分（与清单一致）

- 815 个测试不整体删除，只随功能删。
- 高危审批、幂等、取消、恢复、回收、容量、认证是红线，必须保留。
- 压测 / 弹性对照 / 混淆矩阵 / G3 录屏降为手动或归档。
- 分类器继续暂缓（规则层 94.3% 已够用）。
- `print(1)` 短进程不代表真实负载，改用 CSV 分析 / 图表 / 文件读写。
- 测试分三层（日常 ≤60 s / 阶段约 6 min / 手动专项）。
- 不设“砍到多少测试”的目标。

---

## 3. 我要修正的三处

### 3.1 CLI 控制台：保留 `--json` 极简版，不要全删

| 项 | 清单建议 | 我的建议 |
|---|---|---|
| `scripts/console_overview.py` | 删除 | **保留 `--json` 极简模式（约 30 行）**，删掉展示型排版 |

理由：CLI 的真实价值不是“第二个界面”，而是**前端/后端挂掉时还能看数据**：

- 后端起不来，前端白屏，API 打不开；
- 数据目录配错、DB 损坏，需要直接查 SQLite；
- 排障时不想临时写 SQL。

成本几乎为零，收益是故障时有一条不依赖服务进程的读路径。
如果确认“从来不用”，再删不迟——但不要在精简时顺手删掉唯一的离线诊断入口。

### 3.2 `model_policy`：同意删，但要写清删除范围

它不是 UI 开关，而是 `RouteDecision` 字段 + 事件 payload。所谓“表面配置”其实是：

- `src/routing/router.py` 的 `model_policy` 字段与赋值；
- `route_decided` 事件里的 `model_policy`；
- `docs/ROUTER-REPORT.md`、`docs/design-intent-router.md` 里“按策略切模型”的表述；
- 相关断言（`tests/test_intent_router.py` 等）。

**建议**：按 B 方案删除以上四项，并在设计文档里留一句“成本路由未实现，已移除字段”。
不做真实切换的理由：同时维护模型选择、成本估算、降级链会把路由拖成第二个系统。

### 3.3 压测不能完全手动：阶段门禁保留 60 秒冒烟负载

| 项 | 清单建议 | 我的建议 |
|---|---|---|
| 负载回归 | 全部降为手动 | 保留 **60 秒 / 4 RPS** 的冒烟负载进阶段门禁 |

冒烟只验四件事，不追求数字：

1. 能提交、能完成；
2. 队列有上限，不会无限积压；
3. 429 语义正常（满队列返回明确错误）；
4. 客户端能读到终态。

成本约 1 分钟，能挡住“改了队列导致全挂”的低级错误。
10 分钟长压测、固定/弹性对照仍然只在调度/队列/沙箱实现变化时手动跑。

## 4. 清单漏掉的两项（与“数据不损坏”直接相关）

### 4.1 备份与恢复演练（优先级最高）

个人版最大的风险不是性能，是 **SQLite 损坏 / 误删 / 迁移失败**。当前没有任何“备份 → 恢复 → 校验”的测试。

建议新增：

- `scripts/backup_data.py`：复制各 `.db` 到备份目录，逐个 `PRAGMA integrity_check`；
- 集成测试：写入数据 → 备份 → 破坏原库 → 恢复 → 数据一致；
- 迁移测试：老库副本跑迁移后可读（D6 已有部分，补齐恢复路径）。

### 4.2 本地暴露面检查

单用户 ≠ 无认证。需要一条检查/测试：**服务默认只 bind `127.0.0.1`**；若配置为 `0.0.0.0`，启动时至少输出警告。

理由：同局域网的其他设备可以直接调 `/v1` 和 `/auth/*`，而当前只靠“配置正确”保证安全。

### 4.3（补充）删除时的防误删检查

“删功能 + 删测试”必须在同一次提交完成，删完立刻跑全量，并确认红线测试文件还在：

```powershell
# 这几类文件不能消失
Get-ChildItem tests -Recurse -Filter '*.py' |
  Where-Object { $_.Name -match 'routing_policy|exec_cancel|single_user' }
```

红线清单：`test_routing_policy.py`、`test_agent_stream.py`（取消/澄清）、`tests/integration/test_platform_exec_cancel.py`、`tests/integration/test_single_user_surface.py`、`scripts/verify_w34_residue.py`。

## 5. 删除范围必须精确：邀请码 ≠ 整套认证

清单说“删除邀请码存储层实现与多角色组合测试”，方向对，但**不能连坐**：

| 删除 | 保留 |
|---|---|
| `auth_invites` 表与迁移 | `auth_users`、`auth_sessions` |
| `issue_invite`、`register`（邀请注册） | `bootstrap_owner`、`login`、`session_user`、`set_password` |
| 多角色组合测试（member/trusted/admin） | owner 登录、首启建站长、忘记密码 |
| 角色 CHECK 里的非 owner 取值？（可选） | `owner` 角色与权限判断 |

原因：站长登录、会话、密码重置都依赖 users/sessions；把“多用户”整体删掉会误伤登录本身。
建议先做一次引用扫描（`grep -rn "issue_invite\|register(" src tests`），确认只删邀请码相关路径。

## 8. 一句话结论

> **同意删“为其他用户服务”的功能，不同意删“故障时还能看数据、数据坏了还能恢复、改了队列还能被挡住”的能力。**

这三样（CLI 只读诊断、备份恢复、冒烟负载）成本都很低，但正好对应个人版最怕的三件事：服务挂了、数据没了、改坏了不知道。
