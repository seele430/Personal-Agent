# 弹性计算平台可视化界面 · 计划表

> 日期：2026-11-06
> 目标：在 Personal Agent 内做一个**可操作**的平台控制台，替代“看页面 + 敲 curl”的割裂体验。
> 约束：单用户、本地优先；不新建服务/仓库；复用现有认证、数据库、测试体系。

---

## 1. 现状与差距

| 已有 | 差距 |
|---|---|
| 只读控制台 `/console/overview` + 「平台」页 | 不能建沙箱、不能执行、不能取消/销毁 |
| `/v1` 完整 API（create/exec/cancel/destroy/nodes） | 页面与 API 割裂，试平台要开终端 |
| 节点注册/租约/cordon/drain 后端 | 页面只显示节点，不能操作 |
| 队列/背压/指标 | 只有瞬时值，没有趋势 |
| 扩缩容控制器 + 对照仿真 | 页面不可见、参数不可调 |

**结论**：不是从零做，而是把已有能力“搬进页面并加保护”。

---

## 2. 信息架构（5 个区，单页内切换）

```
平台控制台
├─ 总览       并发沙箱 / 活跃·排队 / 成功率 / p50·p99 / 最近告警
├─ 节点       容量条、租约、cordon/drain/register/remove
├─ 沙箱       列表（state/ttl/node/workspace）+ 新建 + 销毁
├─ 执行       提交命令、取消、输出、exit、traceparent、时间线
└─ 弹性       desired_capacity 模拟器 + 扩缩容决策时间线（只读演示）
```

保留现有「最近路由决策」卡片，作为总览的一部分。

---

## 3. 交互与 API 设计

### 3.1 读接口（扩展现有）

| 接口 | 内容 |
|---|---|
| `GET /console/overview` | 已有：queue / nodes / sandboxes 计数 / execs / routes |
| `GET /console/sandboxes?state=&limit=` | 沙箱列表（含 node、ttl、created_at） |
| `GET /console/nodes` | 节点 + 活跃数 + 容量利用率 |
| `GET /console/series?minutes=30` | 按分钟聚合：exec 开始/成功/失败、并发沙箱、队列峰值 |
| `GET /console/execs/{id}` | 单条执行详情（stdout 尾部、exit、traceparent） |

### 3.2 写接口（P1，均需登录）

| 接口 | 动作 | 保护 |
|---|---|---|
| `POST /console/actions/sandbox` | 建沙箱（workspace/ttl） | 参数校验 + 速率限制 |
| `POST /console/actions/exec` | 提交命令 | 命令长度/超时校验 |
| `POST /console/actions/exec/{id}/cancel` | 取消 | 幂等 |
| `POST /console/actions/sandbox/{id}/destroy` | 销毁 | **前端二次确认** + 审计 |
| `POST /console/actions/node/{id}/cordon\|drain` | 节点操作 | 前端确认 |
| `POST /console/actions/node` | 注册节点（演示用） | 仅容量/ID |

**实现要点**：把 `platform_api` 里创建沙箱/提交 exec 的逻辑抽到 `src/platform/ops.py`，
`/v1` 与 `/console/actions/*` 共用，避免两套逻辑漂移。

### 3.3 认证与权限

- 读接口：登录用户可读（沿用 `get_current_user`）。
- 写接口：登录 + 站长角色（`owner`）；本地未配 token 时 `/v1` 仍开放，但控制台动作走用户会话。
- 不引入多租户；`X-Tenant-Id` 固定 `default`。

---

## 4. 界面细节（避免过度设计）

- **不做图表库**：趋势用内联 SVG 折线 + CSS 容量条，避免新增依赖。
- **不做 WebSocket**：10 秒轮询，页面刷新不丢状态。
- **危险操作**：销毁/取消/摘节点都要 `confirm()` 二次确认，并在按钮旁显示对象 ID。
- **空状态**：没有沙箱/执行时给“去建一个”的引导，而不是空白。
- **错误**：区分 401（重新登录）、429（队列满，显示 Retry-After）、5xx（后端不可用）。

## 5. 分阶段计划

### P0 只读增强（1.5 天）

| # | 任务 | 产出 | 验收 |
|---|---|---|---|
| P0.1 | `series` 聚合接口 + 进程内队列采样（ring buffer，重启丢失） | `src/console_api.py` | 单测：30 分钟窗口、空库 |
| P0.2 | 总览卡片（并发/队列/成功率/p99） | `PlatformView.tsx` | 数字与 `/console/overview` 一致 |
| P0.3 | 节点表（容量条、租约剩余、cordon 标记） | 同上 | 三节点模拟下显示正确 |
| P0.4 | 沙箱表 + 执行表（筛选 state、分页 limit） | 同上 + API | Playwright：列表渲染与筛选 |
| P0.5 | 趋势 SVG（exec 成功/失败、队列峰值） | 同上 | 截图留证 |

### P1 操作层（1.5 天）

| # | 任务 | 产出 | 验收 |
|---|---|---|---|
| P1.1 | 抽 `ops.py`：create/exec/cancel/destroy 共用逻辑 | `src/platform/ops.py` | `/v1` 既有测试全绿 |
| P1.2 | 控制台写接口 + 审计事件 | `console_api.py` | 401/403/参数错误测试 |
| P1.3 | 前端动作：建沙箱、跑命令、取消、销毁 | 组件 + 表单 | 浏览器走通一条完整链路 |
| P1.4 | 节点 cordon/drain/注册 | 同上 | cordon 后新沙箱不再落到该节点 |
| P1.5 | 二次确认 + toast 错误提示 | 同上 | 误点不会直接销毁 |

### P2 弹性面板（1 天）

| # | 任务 | 产出 | 验收 |
|---|---|---|---|
| P2.1 | `desired_capacity` 模拟器（运行/排队/容量/headroom 输入） | 页面组件 | 结果与 `autoscale.py` 一致 |
| P2.2 | 决策时间线：扩容稳定、缩容冷却、事件 | 页面 | 用仿真数据回放 |
| P2.3 | 明确标注“只演示，不自动改生产” | 文案 | 页面上可见 |

**合计约 4 个工作日**（不含压测/录屏）。

## 6. 测试策略

| 层 | 内容 |
|---|---|
| 后端单测 | `series` 聚合、动作参数校验、权限（非 owner 拒绝） |
| 集成 | 控制台动作 → 平台状态真实变化（建/跑/取消/销毁） |
| Playwright | 5 个区切换、建沙箱→执行→取消→销毁、cordon 后调度、错误态与空态 |
| 回归 | 全量 829 + 新增；CI 三 job 保持绿 |

关键红线（不因 UI 放松）：

- 销毁/取消必须有确认；
- 高危动作写审计；
- 前端不得绕过 `get_current_user` 直接调 `/v1` 写接口。

---

## 7. 风险与边界

| 风险 | 应对 |
|---|---|
| 单机无真实多节点 | 节点标注“逻辑节点”，不宣称集群 |
| 自动扩缩容无真实对象 | P2 只做模拟器，不自动改生产 |
| 轮询造成额外负载 | 10 秒间隔、页面隐藏时暂停 |
| 新增依赖膨胀 | 不引图表库/状态库，用内联 SVG + 现有 React |
| 动作误操作 | 二次确认 + 审计 + 只对 owner 开放 |

---

## 8. Definition of Done

- [ ] 5 个区在一屏内可切换，移动端不横向溢出
- [ ] 建沙箱 → 执行 → 取消 → 销毁 全流程在页面完成
- [ ] 节点 cordon 后新沙箱不再落到该节点
- [ ] 趋势与容量条数据来自真实 DB/采样，不是假数据
- [ ] 危险操作有确认与审计
- [ ] 后端新增测试 + Playwright + 全量回归通过
- [ ] 页面明确标注“单机 / 逻辑节点 / 弹性面板为模拟”

---

## 9. 建议的开工顺序

1. **P0**（只读增强）——不碰写路径，风险最低，先把“能看懂”做好；
2. **P1**（操作层）——抽 `ops.py` 是关键，先重构再接 UI；
3. **P2**（弹性面板）——纯展示，最后做。

先做 P0 还是直接 P1？我建议 **P0 → P1 → P2**，因为你现在最缺的是“看得懂正在发生什么”，而不是少一个按钮。
