# 单用户 Agent 沙箱威胁模型（D1 草案）

> 日期：2026-11-02
> 状态：D1 草案；D2 固化平台契约，D12 / D33 用负向测试更新实测结论。
> 使用边界：本地单用户，但允许同一用户并行运行多个独立 run 和沙箱。

## 1. 安全承诺

| 层 | 本周期定位 | 明确不承诺 |
| --- | --- | --- |
| tier1 process | 受控执行环境，用于受信任代码或开发演示 | 不是强安全沙箱；不用于证明恶意代码隔离 |
| tier2 container | 在已完成负向测试的范围内提供更强隔离 | 不承诺内核逃逸防护、恶意宿主防护或未测试的网络 / 文件系统边界 |
| 审批策略 | 对危险工具增加人工确认 | 审批不能替代隔离，也不能把危险命令自动变成安全命令 |
| 测试运行器 guard | 测试数据目录、SQLite 和 socket 的第二道防线 | `scripts/run_guarded_tests.py` 已明确说明它不是完整 OS 沙箱 |

“单用户”只表示不做租户边界，不表示模型生成的命令天然可信，也不表示并行任务可以互相破坏。

## 2. 保护对象

- 宿主工作区外的文件、个人数据和 SQLite 数据库。
- `.env`、API key、Bearer token、NTFY topic 等凭据；真实 `.env` 不纳入 Git / 证据。
- 宿主网络、内网服务与外部 HTTP 目标。
- 并行 run 的工作区、进程、输出与沙箱状态。
- 控制面数据库、节点租约、幂等记录和 trajectory 完整性。
- 本机 CPU、内存、磁盘、进程数和文件描述符。

## 3. 输入与信任假设

### 3.1 输入假设

- 用户本人不是本期的攻击者，但可能误粘贴危险命令或敏感内容。
- 模型输出可能错误、幻觉或受到检索内容 / 工具结果中的提示注入影响。
- 工具参数、HTTP 响应和文件内容都应当作不可直接信任的数据。
- 只有明确标注为“不可信代码演示”时，才按恶意输入讨论；tier1 不承担该演示。

### 3.2 可信组件

- 现有服务端认证与归属校验，在其已经测试的范围内可信。
- 控制面、节点服务和 runner 属于本平台组件，但它们之间的调用仍需验证身份、状态和参数。
- SQLite 适合单机控制面；数据库文件本身仍需防止被工具工作负载直接读写。

## 4. 信任边界

目标链路：

```text
Browser / CLI
    │ 用户输入、取消
    ▼
Agent 助手 / FastAPI
    │ run、tool request、approval
    ▼
沙箱控制面
    │ create / exec / cancel / destroy
    ▼
节点进程
    │ 带 generation 的节点状态与执行请求
    ▼
runner
    │ 受限环境、timeout、输出上限
    ▼
工具子进程 ─── 工作区 / 网络 / 环境变量 / 其他并行 run
```

需要单独审视的边界：

1. **模型到工具注册表**：模型只能选择工具，不能自行扩大工具名、参数或权限。
2. **助手到控制面**：所有 exec 都要有明确 run / step / exec 关联和取消语义。
3. **控制面到节点**：节点状态必须带 generation，旧心跳不能复活过期节点。
4. **runner 到操作系统**：进程创建、终止、资源限制和输出读取不能依赖模型配合。
5. **工作负载到宿主资源**：文件、网络、环境变量和并行 run 必须分别设限。
6. **执行数据到观测存储**：日志和 trajectory 不能原样泄露密钥或无限放大磁盘占用。

## 5. 主要滥用与故障场景

| 场景 | 可能后果 | 本期控制与验收 |
| --- | --- | --- |
| `../`、绝对路径或符号链接逃逸工作区 | 读取或修改宿主文件 | D12 路径负向测试；先解析真实路径，再判断归属，禁止只检查字符串前缀 |
| 子进程继承 `.env`、API key 或 token | 密钥被打印、外发或写入轨迹 | 环境变量默认清洗，采用显式小允许集；日志与 trajectory 脱敏 |
| shell / python 再创建子进程 | 取消只杀父进程，留下孤儿 | runner 进程树清理；D7 / D11 / D34 分阶段验收 |
| 无限输出、死循环、高内存或大量进程 | 本机卡顿、磁盘写满、其他 run 失败 | 输出上限、timeout、全局并发、有界队列；C++ runner 限额若被砍则如实记录缺口 |
| 工具自由访问网络 | 内网探测或数据外发 | 网络按工具显式授权；tier1 无网络隔离时禁止不可信代码；tier2 做网络负向测试 |
| 一个 run 猜测另一个 run 的路径或 ID | 并行任务互相读改 | run 级工作区与归属校验；不同并行 run 的隔离测试 |
| 客户端重试 create / exec | 重复沙箱或重复副作用 | 幂等 key 原子约束、同 key 不同请求体 409、重启后仍保持 |
| 节点旧心跳或延迟响应 | 已过期节点被错误标为 ready | `node_id + generation` 校验；旧 generation 拒绝 |
| 控制面重启但实际进程仍在 | 数据库与实际状态不一致、孤儿累积 | 平台所有权标识与启动对账；不得误杀非本平台进程 |
| 工具参数、结果或日志包含敏感值 | 凭据长期留存在 SQLite / JSONL | 字段白名单、脱敏、输出与保留上限；事故时能够删除对应数据 |
| 磁盘故障注入失控 | 真实宿主数据损坏 | 只允许临时测试卷、配额目录或故障模拟层 |

## 6. 现有控制可以复用什么

- `docs/AGENT_TOOLS.md` 记录了工具名白名单、参数字节上限、单轮副作用上限和身份绑定。
- `docs/AUTH_AND_ISOLATION.md` 记录了现有服务端会话、归属过滤、幂等和并发 / 预算原子性。
- `src/core/trace_store.py` 已有 span 关联与批量落盘能力。
- `scripts/run_guarded_tests.py` 已能替换真实模型凭据并隔离测试数据库。

这些控制是平台化的基础，但都不能替代工作负载的 OS 级隔离。

## 7. D2 必须固化的安全相关契约

- 工作区根目录如何配置，real path 与符号链接如何判断。
- 工具默认环境变量允许集，网络默认策略及各工具例外。
- exec 的 timeout、cancel、输出上限和最终状态。
- create / exec 的幂等边界；哪些操作有副作用，哪些可安全重试。
- 沙箱与 exec 状态机，以及 404 / 409 / 410 / 429 的语义。
- 节点 generation、租约过期和对账所有权标识。
- trajectory 的脱敏、事件顺序、schema_version 和保留策略。

## 8. 不在本周期承诺的范围

- 多租户与租户间安全隔离。
- 宿主管理员已失陷、操作系统内核逃逸、恶意 hypervisor。
- 真实多机集群与跨区域一致性。
- 生产级供应链安全、镜像签名、密钥管理平台和审计合规。
- trajectory 回放或训练数据管道的安全验证。

## 9. D1 未决问题

- Windows 下 tier1 的进程树与资源限制哪些由 Python runner 承担，哪些等 C++ Job Object。
- tier1 的网络限制是否只能做到“工具级允许”，若是，文档必须醒目标明。
- 工具结果需要保存多少内容才能兼顾调试与脱敏；不能为了 trajectory 完整度默认记录全部敏感参数。
- 沙箱回收后的 tombstone 与轨迹保留期如何区分。

这些问题不是安全实现的豁免项；在实测前统一按“未证明、未承诺”处理。

## 10. D11 实测状态（2026-11-03）

已落地的控制（都有测试与证据）：

- **进程树清理**：runner 启动后先被分配进独立 Windows Job Object，宿主随后才
  通过 stdin 放行任务说明；取消 / 超时 / 输出超限一律 `TerminateJobObject`，
  并且只在 `ActiveProcesses == 0` 之后才写终态。证据见
  `docs/evidence/d11-runner-tests.txt` 与 `docs/evidence/d11-live-cancel.json`
  （父进程与子进程 PID 均不再存活）。
- **环境清洗**：子进程只拿到 `PATH / PATHEXT / SYSTEMROOT / WINDIR / COMSPEC /
  TEMP / TMP / LANG / LC_ALL`，外加平台自己的 `PERSONAL_AGENT_TIER1=1`；
  tier1 模式下不执行 `load_dotenv`，宿主 `.env` 里的凭据不进入子进程。
- **工具位置**：`agent_stream` 与旧 JSON 聊天路径都不再在宿主调用工具 handler；
  两者都经过 `src/platform/exec_service.py`。宿主只做策略、参数与身份检查。
- **输出与终态**：stdout + stderr 共用一个字节预算；超限先清树，再落
  `failed / OUTPUT_LIMIT_EXCEEDED`。
- **取消顺序**：trajectory 先记 `exec_cancel_requested`，进程树清空之后才写
  `exec_finished / cancelled`；清理失败落 `failed / RUNNER_CLEANUP_FAILED`，
  不伪造 cancelled。

仍然不承诺（D11 不改变这些结论）：

- tier1 没有 OS 级网络隔离，也没有文件系统 jail。提醒工具通过平台显式授予的
  `--data-dir` 打开自己的数据库，这是**显式授权**，不是隔离。
- 文件工具的相对路径、`..` 与符号链接逃逸测试属于 D12；D11 只保证在分配好的
  工作区里启动，不保证工具自身不会越界。
- 「先分配 Job Object、再通过 stdin 放行」关掉的是启动竞态，不构成对恶意
  runner 的防护 —— tier1 只跑受信任代码。
- CPU / 内存 / 进程数限额要等 D34 的 C++ runner；D11 只控制时间、输出与进程树。

## 11. D12 实测状态（2026-11-03）

- **路径归属**：`src/tools/sandbox_tools.py` 只接受工作区内相对路径，先解析
  real path 再判断是否仍在工作区；`..`、绝对路径、盘符路径、目录联接
  （junction）逃逸都有负向测试，证据见 `docs/evidence/d12-sandbox-tools.txt`。
  判断依据是解析后的路径归属，不是字符串前缀。
- **工作区**：同一次 run 共享一个沙箱工作区（`open_run_sandbox`），run 结束
  （成功 / 取消 / 失败）统一回收，文件不跨 run 残留。
- **工具面**：`read_file` / `list_dir` 对模型开放（allow）；`write_file` /
  `run_shell` / `run_python` / `http_get` 已在注册表中，但策略是 ask 且不暴露
  给模型 —— 在 D13 接入审批交互之前，它们无法通过对话触发。
- **仍然不承诺**：`run_shell` / `run_python` 一旦执行就是任意代码，tier1 没有
  网络隔离也没有文件 jail；`http_get` 只做协议 / 超时 / 输出上限，不做 SSRF
  目标限制（网络允许集等 D13 之后再定义）。

## 12. D15 平台 HTTP 面的边界（2026-11-03）

- `/v1`（create / exec / get_exec / cancel / destroy）**没有接入登录认证**：
  它是本机单用户控制面，服务只监听 `127.0.0.1`。任何能在本机发 HTTP 的进程
  都可以创建沙箱并执行命令。D21 做多租户配额时必须同时补认证与归属校验，
  在那之前**不能把 `/v1` 暴露到非本机地址**。
- `exec` 的 `command` 是 argv 直传，能跑任意命令；tier1 依旧不是安全沙箱。
- 沙箱 ID 由服务端生成（`sbx_` + 32 位 hex），exec 只接受已登记且未回收的
  沙箱；销毁后返回 410，不会重新拉起进程。
- 幂等只覆盖 create：同 key 重试不会多建沙箱；exec 明确不承诺重放。
