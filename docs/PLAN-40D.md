# 40 天改造计划：Personal Agent → Agent 助手 + 沙箱平台

> 目标岗位：DeepSeek「Agent 弹性计算研发工程师 · 平台开发方向」
> 起止：D1（体检）— D40（交付）。每天按表打卡，每周日记录口径数字。
> 主线占比：**平台 60% / 助手 30% / 前端 10%**。任何取舍按这个比例判。

---

## 0. 一句话定位

平台具备节点管理、生命周期、可观测闭环与压测数据。

面试开场白应该能一口气说完：

> 我做了一个 Agent 助手，它的工具调用全部经过自建沙箱平台；平台有节点租约、幂等创建、TTL 回收，
> 我给它做了可观测闭环和饱和曲线，并在 16GB 单机上测出了拐点。

---

## 1. 不做的事（先划掉，防止范围膨胀）

- ❌ 子代理 / 技能系统 / MCP / 多模态
- ❌ 语音 TTS 新特性（保留现有代码，不投入）
- ❌ 知识库重构（保留 ingest/retrieve，不动）
- ❌ 移动端、桌面打包（现有 PyInstaller 保留不维护）
- ❌ 真正的多机集群（用**单机三进程**模拟三节点，文档里说清楚）
- ❌ raft / etcd / 2PC（用租约 + 幂等 + 对账替代，并说明为什么不选）

## 7. 每日 15 分钟收尾（机械执行，不靠记性）

1. 跑一次全量测试，记下数字；
2. 在 `docs/journal.md` 写三行：今天做了什么 / 卡在哪 / 明天第一件事；
3. `git commit`（信息格式 `dXX: 一句话`）。

> 40 天里最贵的不是写代码，是**忘记上周卡在哪**。这三行就是给未来的自己留证据。

## 8. Definition of Done（D40 交付物）

- [ ] 仓库可 `clone` → 三条命令跑起来（README 的 quickstart ≤ 3 分钟）
- [ ] 演示视频 ≤ 3 分钟：助手 → 工具 → 沙箱 → 轨迹 → 面板
- [ ] `SLO.md`：3 条 SLO + 实测达成情况
- [ ] `docs/bench/`：压测脚本 + CSV + 饱和曲线图
- [ ] `docs/runbook.md`：常见故障与处置
- [ ] `docs/postmortem.md`：至少一次真实故障复盘（含时间线、根因、整改）
- [ ] `docs/architecture.md`：一张图 + 三个 trade-off 说明
- [ ] 简历段落 200 字（不含“我做了 DSec”这类表述）
- [ ] 全量测试绿，且用例数 ≥ 基线数
